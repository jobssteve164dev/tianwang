## 2. 核心实现 (Core Implementation)

### a. 方法论/设计思路

本阶段采用了多层次、跨平台的数据收集与主动防护架构设计：

1. **跨平台客户端架构**: 使用Electron框架开发桌面客户端，支持Windows、Linux、macOS三大主流操作系统，同时开发C/C++轻量级OpenWrt客户端，实现网关级监控。

2. **分层服务设计**: 采用模块化设计，将系统监控、网络监控、安全服务、防火墙服务等功能分离，每个服务独立运行，通过事件机制协调工作。

3. **实时通信机制**: 基于WebSocket实现客户端与服务器的实时双向通信，支持心跳检测、断线重连、数据缓冲等高可用特性。

4. **主动防护系统**: 集成跨平台防火墙引擎，支持自动威胁阻断、IP白名单/黑名单管理、策略分发等功能。

async addBlockRule(ip, reason) {
    let command;
    const ruleId = `tianwang_block_${Date.now()}_${Math.random().toString(36).substr(2, 9)}`;

    switch (this.platform) {
        case 'win32':
            command = `netsh advfirewall firewall add rule name="${ruleId}" dir=in action=block remoteip=${ip}`;
            break;
        case 'linux':
            command = `iptables -A INPUT -s ${ip} -j DROP -m comment --comment "${ruleId}: ${reason}"`;
            break;
        case 'darwin':
            command = `echo "block drop from ${ip} to any" | pfctl -a tianwang -f -`;
            break;
        default:
            throw new Error(`不支持的平台: ${this.platform}`);
    }

}

## 5. 自我评估与学习 (Self-Assessment & Learning)

*   **遇到的挑战**: 
    - 跨平台防火墙API的差异性较大，需要针对每个平台实现不同的命令调用逻辑
    - OpenWrt的UCI配置系统相对复杂，需要深入理解其配置文件结构和API使用

*   **学到的教训**: 
    - 在设计跨平台服务时，应该优先考虑平台差异，采用策略模式或工厂模式来处理不同平台的实现
    - WebSocket服务的稳定性对整个系统至关重要，需要实现完善的错误处理和重连机制
    - 模块化设计能够有效降低系统复杂度，每个服务独立运行，便于调试和维护

*   **技术收获**:
    - 深入掌握了Electron跨平台桌面应用开发技术
    - 学习了OpenWrt系统的UCI配置管理和网络监控API
    - 实践了WebSocket实时通信和Node.js事件驱动编程模式
    - 掌握了跨平台防火墙规则管理的技术实现方案
