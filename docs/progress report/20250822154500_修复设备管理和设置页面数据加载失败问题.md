## 2. 核心实现 (Core Implementation)

### a. 方法论/设计思路
通过分析日志发现两个主要问题：
1. **数据库字段名不匹配**：代码中使用驼峰命名（如`agentId`, `registeredAt`），但数据库模型使用下划线命名（如`agent_id`, `registered_at`）
2. **权限验证问题**：通知配置API需要`admin`或`security_analyst`权限，但前端用户角色是`super_admin`

### b. 主要变更文件 (Key Changed Files)
*   `MODIFIED`: `server/src/routes/devices.js`
    *   修复数据库字段名映射问题
    *   将`agentId`改为`agent_id`
    *   将`lastSeen`改为`last_seen`
    *   将`registeredAt`改为`registered_at`
    *   将`systemInfo`改为`system_info`
*   `MODIFIED`: `server/src/routes/notifications.js`
    *   修复权限验证问题
    *   将`super_admin`角色添加到允许的角色列表中

### c. 关键代码片段
**设备路由字段名修复**:
```javascript
// 修复前

  'id', 'agentId', 'name', 'hostname', 'platform', 'arch', 'version',
  'status', 'lastSeen', 'registeredAt', 'capabilities', 'systemInfo'
]

// 修复后
attributes: [
  'id', 'agent_id', 'name', 'hostname', 'platform', 'arch', 'version',

]
```
