# 开发环境日志系统使用指南

## 概述

天网安全监控系统的开发环境日志系统是一个独立的、流式日志收集器，专门用于收集和管理开发环境中所有服务的console日志。

## 系统特性

- **流式收集**: 实时收集客户端、AI引擎、服务端的所有console日志
- **自动滚动**: 限制最大100000行，超出自动覆盖最开始的输出
- **独立运行**: 独立于已有的logger系统，不影响现有日志功能
- **自动管理**: 随系统启动和关闭，每次启动时清理并生成新文件
- **彩色输出**: 支持彩色日志显示，便于快速识别不同服务和错误级别

## 文件结构

```
scripts/
├── dev-logger.js          # 日志收集器主程序
├── dev-log-viewer.js      # 交互式日志查看器
└── dev-log-tail.js        # 快速日志查看工具

logs/
└── dev/
    └── dev-console.log    # 开发环境日志文件

dev-start-with-logger.sh   # 集成日志收集器的启动脚本
```

## 快速开始

### 1. 启动开发环境（集成日志收集器）

```bash
# 使用集成日志收集器的启动脚本
./dev-start-with-logger.sh
```

这个脚本会自动：
- 启动日志收集器
- 启动所有服务（AI引擎、服务端、客户端）
- 收集所有服务的console日志到 `logs/dev/dev-console.log`

### 2. 启动增强版开发环境（包含浏览器日志收集）

```bash
# 使用增强版启动脚本
./dev-start-enhanced.sh
```

这个脚本会：
- 启动增强版日志收集器（包含WebSocket服务器）
- 启动所有服务（AI引擎、服务端、客户端）
- 自动收集浏览器控制台日志
- 收集所有服务的console日志到 `logs/dev/dev-console.log`

### 2. 查看日志

#### 快速查看最后50行日志
```bash
node scripts/dev-log-tail.js
```

#### 查看最后100行日志
```bash
node scripts/dev-log-tail.js 100
```

#### 查看包含"error"关键词的日志
```bash
node scripts/dev-log-tail.js 50 error
```

#### 实时监控日志
```bash
node scripts/dev-log-tail.js watch
```

#### 实时监控特定服务的日志
```bash
node scripts/dev-log-tail.js watch server
```

### 3. 交互式日志查看器

启动交互式日志查看器，提供更多功能：

```bash
node scripts/dev-log-viewer.js
```

#### 可用命令

- `help` - 显示帮助信息
- `tail [lines]` - 查看最后N行日志 (默认50行)
- `watch` - 实时监控日志
- `filter service <name>` - 按服务过滤 (CLIENT, SERVER, AI-ENGINE, SYSTEM)
- `filter keyword <text>` - 按关键词过滤
- `filter level <level>` - 按级别过滤 (ERROR, WARNING, INFO)
- `clear` - 清除所有过滤器
- `stats` - 显示日志统计信息
- `search <keyword>` - 搜索关键词
- `quit` - 退出

## 日志格式

日志文件采用统一的格式：

```
[时间戳] [服务名] 日志内容
```

### 时间戳格式
- ISO 8601格式：`2024-01-15T10:30:45.123Z`

### 服务标识
- `SYSTEM` - 系统级日志（启动、关闭、滚动等）
- `CLIENT` - 客户端日志
- `SERVER` - 服务端日志
- `AI-ENGINE` - AI引擎日志
- `CLIENT-ERROR` - 客户端错误日志
- `SERVER-ERROR` - 服务端错误日志
- `AI-ENGINE-ERROR` - AI引擎错误日志
- `BROWSER` - 浏览器控制台日志
- `BROWSER-ERROR` - 浏览器错误日志
- `BROWSER-STACK` - 浏览器错误堆栈
- `BROWSER-RAW` - 浏览器原始日志

### 颜色编码
- **青色** - 时间戳
- **黄色** - 服务名
- **红色** - 错误信息
- **黄色** - 警告信息
- **绿色** - 普通信息

## 配置选项

### 日志文件位置
默认位置：`logs/dev/dev-console.log`

### 最大行数限制
默认：100,000行

### 滚动策略
当达到最大行数时：
1. 关闭当前日志文件
2. 重命名为 `dev-console.log.{timestamp}`
3. 创建新的日志文件
4. 继续收集日志

## 故障排除

### 1. 日志文件不存在
```
❌ 日志文件不存在: logs/dev/dev-console.log
请先启动开发环境: ./dev-start-with-logger.sh
```

**解决方案**: 确保先启动开发环境

### 2. 日志收集器启动失败
检查：
- Node.js是否正确安装
- 脚本文件是否存在
- 端口是否被占用

### 3. 日志文件过大
系统会自动滚动日志文件，但您也可以手动清理：

```bash
# 清理日志文件
rm logs/dev/dev-console.log*

# 或者只保留最新的几个文件
ls -t logs/dev/dev-console.log.* | tail -n +4 | xargs rm
```

### 4. 实时监控不工作
- 确保日志文件存在
- 检查文件权限
- 重启日志查看器

## 高级用法

### 1. 自定义日志收集器

您可以修改 `scripts/dev-logger.js` 来自定义：
- 日志文件路径
- 最大行数限制
- 滚动策略
- 服务启动方式

### 2. 集成到CI/CD

在持续集成环境中，可以这样使用：

```bash
# 启动开发环境
./dev-start-with-logger.sh &

# 等待服务启动
sleep 30

# 运行测试
npm test

# 查看测试期间的日志
node scripts/dev-log-tail.js 100

# 停止服务
pkill -f "dev-start-with-logger.sh"
```

### 3. 日志分析

使用标准工具分析日志：

```bash
# 统计错误数量
grep -c "ERROR" logs/dev/dev-console.log

# 查看特定时间段的日志
grep "2024-01-15T10:" logs/dev/dev-console.log

# 提取特定服务的日志
grep "\[SERVER\]" logs/dev/dev-console.log

# 实时监控错误
tail -f logs/dev/dev-console.log | grep "ERROR"
```

## 常见问题

### Q: 为什么看不到某些服务的日志？
A: 确保该服务正在运行，并且日志收集器已启动。

### Q: 日志文件增长太快怎么办？
A: 系统会自动滚动日志文件，您也可以调整最大行数限制。

### Q: 如何查看历史日志？
A: 滚动后的日志文件会保存为 `dev-console.log.{timestamp}` 格式。

### Q: 可以同时运行多个日志查看器吗？
A: 可以，但建议只运行一个实时监控实例。

### Q: 日志收集器会影响性能吗？
A: 影响很小，日志收集器使用流式处理，内存占用很低。
