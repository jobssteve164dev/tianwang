# 天网安全监控系统 - 开发环境清理指南

## 概述

本文档介绍天网安全监控系统开发环境的进程清理功能，确保在开发过程中能够彻底清理所有相关进程，避免端口冲突和资源占用问题。

## 清理功能特性

### 1. 多层次清理策略

- **基于PID文件清理**: 通过记录的PID文件精确停止服务
- **基于进程名称模式清理**: 使用正则表达式匹配相关进程
- **基于端口清理**: 清理占用项目端口的进程
- **子进程清理**: 防止僵尸进程残留

### 2. 智能清理机制

- **优雅停止**: 首先尝试SIGTERM信号优雅停止
- **强制终止**: 如果优雅停止失败，使用SIGKILL强制终止
- **验证清理**: 清理后验证是否还有残留进程
- **详细日志**: 提供详细的清理过程日志

### 3. 安全保护

- **系统进程保护**: 避免误杀系统关键进程
- **用户确认**: 激进清理模式需要用户确认
- **备份机制**: 清理前备份重要配置文件

## 使用方法

### 1. 自动清理（推荐）

启动开发环境时，脚本会自动设置信号处理，在退出时自动清理所有进程：

```bash
# 启动开发环境
./dev.sh

# 按 Ctrl+C 退出，会自动清理所有进程
```

### 2. 手动清理

#### 查看当前状态

```bash
# 仅查看当前进程和端口状态
./scripts/dev-cleanup.sh --status
```

#### 标准清理

```bash
# 执行标准清理（推荐）
./scripts/dev-cleanup.sh
```

#### 激进清理

```bash
# 执行激进清理（包括所有Node.js进程）
./scripts/dev-cleanup.sh --aggressive
```

#### 清理并删除日志

```bash
# 清理进程并删除日志文件
./scripts/dev-cleanup.sh --clean-logs
```

#### 组合使用

```bash
# 激进清理并删除日志
./scripts/dev-cleanup.sh --aggressive --clean-logs
```

### 3. 测试清理功能

```bash
# 运行完整测试
./scripts/test-cleanup.sh

# 创建测试进程
./scripts/test-cleanup.sh --simulate

# 清理测试进程
./scripts/test-cleanup.sh --cleanup-test
```

## 清理范围

### 进程清理

- **增强版日志收集器**: `node.*dev-logger-enhanced.js`
- **服务端**: `node.*server/src/index.js`
- **客户端**: `node.*client/node_modules/.bin/react-scripts`
- **AI引擎**: `python.*server/ai-engine/src/main.py`
- **Kafka服务**: `kafka-server-start`, `kafka-topics`
- **相关工具**: `kafka-console-producer`, `kafka-console-consumer`

### 端口清理

- **AI引擎**: 8888
- **服务端API**: 5555
- **客户端**: 3333
- **WebSocket**: 8889
- **Kafka**: 9092, 9093

### 文件清理

- **PID文件**: `.enhanced-logger.pid`, `server/.server.pid`, `client/.client.pid`, `server/ai-engine/.ai_engine.pid`, `.kafka.pid`
- **日志文件**: `logs/dev/*.log`, `server/logs/*.log`, `server/ai-engine/logs/*.log`（可选）

## 信号处理

启动脚本会捕获以下信号并自动清理：

- `EXIT`: 脚本正常退出
- `INT`: 中断信号（Ctrl+C）
- `TERM`: 终止信号
- `HUP`: 挂起信号
- `QUIT`: 退出信号
- `ABRT`: 中止信号
- `USR1`: 用户自定义信号1
- `USR2`: 用户自定义信号2

## 故障排除

### 1. 进程无法清理

如果某些进程无法通过脚本清理，可以手动清理：

```bash
# 查找相关进程
ps aux | grep -E "tianwang|dev-logger|ai-engine"

# 强制终止进程
pkill -f "tianwang|dev-logger|ai-engine"

# 或者使用进程ID
kill -9 <PID>
```

### 2. 端口仍被占用

如果端口仍被占用，检查是否是系统进程：

```bash
# 查看端口占用情况
lsof -i :<PORT>

# 如果是系统进程，请手动处理
```

### 3. 权限问题

如果遇到权限问题，确保脚本有执行权限：

```bash
chmod +x scripts/dev-cleanup.sh
chmod +x scripts/test-cleanup.sh
```

## 最佳实践

### 1. 开发流程

1. **启动前**: 使用 `./scripts/dev-cleanup.sh --status` 检查当前状态
2. **启动**: 使用 `./dev.sh` 启动开发环境
3. **退出**: 按 `Ctrl+C` 优雅退出，让脚本自动清理
4. **异常情况**: 使用 `./scripts/dev-cleanup.sh` 手动清理

### 2. 定期维护

- 定期使用 `--clean-logs` 选项清理日志文件
- 在切换分支或重启开发环境前执行清理
- 遇到端口冲突时优先使用清理脚本

### 3. 团队协作

- 在提交代码前确保清理所有本地进程
- 在拉取代码后检查是否有端口冲突
- 共享清理脚本的使用经验

## 注意事项

1. **激进清理模式**: 使用 `--aggressive` 参数会终止所有项目相关的Node.js进程，请谨慎使用
2. **系统进程**: 脚本会保护系统关键进程，不会误杀
3. **数据安全**: 清理操作不会影响项目数据，只会清理进程和临时文件
4. **日志保留**: 默认不会删除日志文件，如需清理请使用 `--clean-logs` 参数
