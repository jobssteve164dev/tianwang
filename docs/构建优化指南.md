# 天网系统构建优化指南

## 🚀 构建缓存优化

### 问题背景
传统的Docker构建每次都会重新下载依赖，导致构建时间过长。我们通过以下方式优化构建速度：

### 优化策略

#### 1. Docker层缓存优化
- **分离依赖安装和代码复制**：先复制package.json，安装依赖，再复制源代码
- **使用多阶段构建**：分离构建环境和运行环境
- **利用BuildKit**：启用Docker BuildKit加速构建

#### 2. npm缓存优化
- **配置npm镜像源**：使用国内镜像源加速下载
- **启用离线模式**：优先使用本地缓存
- **分层缓存策略**：分别缓存生产依赖和开发依赖

#### 3. 并行构建
- **多服务并行构建**：同时构建前端、后端、AI引擎
- **多阶段并行**：依赖安装和代码构建并行进行

## 🐳 Dockerfile优化详解

### 服务器Dockerfile优化
```dockerfile
# 1. 分离依赖安装
FROM node:20-alpine AS deps
COPY package*.json ./
RUN npm ci --only=production

# 2. 构建阶段
FROM node:20-alpine AS builder
COPY package*.json ./
RUN npm ci
COPY src/ ./src/
RUN npm test --if-present

# 3. 生产阶段
FROM node:20-alpine AS production
COPY --from=deps /app/node_modules ./node_modules
COPY --from=builder /app/src ./src
```

### 前端Dockerfile优化
```dockerfile
# 1. 依赖缓存阶段

# 2. 构建阶段
```

## 🔍 缓存管理

### 查看缓存状态
```bash
# 查看Docker缓存
docker system df

# 查看构建缓存
ls -la .build-cache/

# 查看npm缓存
npm cache verify
```

### 清理缓存
```bash
# 清理Docker缓存
docker system prune -a

# 清理构建缓存
rm -rf .build-cache/

# 清理npm缓存
npm cache clean --force
```

### 缓存配置
```bash
# 设置npm镜像源
npm config set registry https://registry.npmmirror.com/

# 启用离线模式
npm config set prefer-offline true

# 设置缓存目录
npm config set cache /tmp/npm-cache
```

## 🚨 常见问题

### 1. 缓存不生效
**原因**：Dockerfile中的COPY指令顺序不当
**解决**：确保package.json在源代码之前复制

### 2. 构建速度仍然很慢
**原因**：网络问题或镜像源问题
**解决**：使用国内镜像源，检查网络连接

### 3. 缓存占用空间过大
**原因**：缓存文件累积过多
**解决**：定期清理旧缓存，设置缓存过期时间

### 4. 并行构建失败
**原因**：资源不足或依赖冲突
**解决**：增加系统资源，检查依赖版本
