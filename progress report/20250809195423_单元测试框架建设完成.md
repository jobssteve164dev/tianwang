```javascript
async function runTests() {
    const results = {
        server: null,
        agents: null,
        integration: null
    };

    // 运行服务端测试
    if (fs.existsSync(serverDir)) {
        results.server = await runCommand('npm', ['test'], serverDir);
    }

    // 运行桌面客户端测试
    if (fs.existsSync(agentsDir)) {
        results.agents = await runCommand('npm', ['test'], agentsDir);
    }

    // 运行集成测试
    if (fs.existsSync(testsDir)) {
        results.integration = await runCommand('npx', ['jest', '--config', 'jest.config.js'], rootDir);
    }
}
```

## 5. 自我评估与学习 (Self-Assessment & Learning)

*   **遇到的挑战**: 
    - 跨平台测试环境配置复杂，特别是OpenWrt的UCI库依赖在macOS上无法直接使用
    - Jest Mock配置需要精确匹配模块导入和依赖关系
    - WebSocket集成测试需要处理异步连接和消息传递的复杂时序问题

*   **学到的教训**: 
    - 测试驱动开发需要在项目初期就建立完整的测试框架，而不是事后补充
    - Mock和Stub的设计需要与实际代码结构紧密配合，避免过度Mock导致测试失去意义
    - 集成测试比单元测试更能发现系统性问题，但调试难度也更大
    - 自动化测试工具能显著提高测试执行效率和一致性
