## 2. 核心实现 (Core Implementation)

### a. 方法论/设计思路
采用了多层次、智能化的进程清理策略，通过以下方式确保彻底清理：
1. **基于PID文件的精确清理**: 通过记录的PID文件精确停止服务
2. **基于进程名称模式的模式匹配**: 使用正则表达式匹配相关进程
3. **基于端口的清理**: 清理占用项目端口的进程
4. **子进程清理**: 防止僵尸进程残留
5. **优雅停止与强制终止**: 先尝试优雅停止，失败后强制终止

### b. 主要变更文件 (Key Changed Files)

## 6. 新增功能特性

### 清理脚本功能
- **状态查看**: `--status` 参数查看当前进程和端口状态
- **标准清理**: 默认模式，安全清理项目相关进程
- **激进清理**: `--aggressive` 参数，包括所有Node.js进程
- **日志清理**: `--clean-logs` 参数，同时清理日志文件
- **组合使用**: 支持多个参数组合使用

### 测试脚本功能
- **完整测试**: 测试所有清理功能
- **模拟测试**: 创建测试进程进行清理测试
- **测试清理**: 清理测试过程中创建的进程

### 文档支持
- **详细指南**: 包含使用方法、最佳实践和故障排除
- **示例命令**: 提供各种使用场景的示例
- **安全提醒**: 明确标注危险操作和注意事项

## 7. 使用建议

1. **日常开发**: 使用 `./dev.sh` 启动，按 `Ctrl+C` 退出自动清理
2. **端口冲突**: 使用 `./scripts/dev-cleanup.sh` 手动清理
3. **彻底清理**: 使用 `./scripts/dev-cleanup.sh --aggressive` 激进清理
4. **定期维护**: 使用 `--clean-logs` 参数清理日志文件
5. **团队协作**: 在提交代码前执行清理，避免影响其他开发者
